## Question

With patch 0042 (grammar clone fix), what is decode speed with 107 tools in the prompt vs 2 tools, at depth 20000?

## Why

4070 session request. Patch 0042 clones the grammar; a long tool list makes a large grammar.

## Plan and gate

Notebook: "P63 (queue 07c): patch 0042 check - bench/agent_depth_probe.py (main) at depth 20000, arm "server",
bin-tier, drafting preset + lookup: PROBE_MANY_TOOLS=105 PROBE_TOOL_CHARS=976 PROBE_PI=1 vs no PROBE_* (2 tools).
Reading: decode tok/s." No gate.

## Method

One server. Three probe runs in order: 2 tools (t2), 107 tools (PROBE_MANY_TOOLS=105, PROBE_TOOL_CHARS=976,
PROBE_PI=1; t107), 2 tools again (t2b). Each run: ask 0 (first request at depth 20000) and ask 1 (follow-up).

## Results

| 8gb-t2 | 2 | 0 | 43.8 | 2205 | 20330 | 0.742 |

| 8gb-t2b | 2 | 0 | 43.7 | 2115 | 516 | 0.735 |

Notebook: "P63: 2 tools 43.8, 107 tools (46,878-token prompt) 34.8 - depth confounded."

## Deviations, incidents, void runs

- Depth confound: the 107-tool prompt is 46,878 tokens, not ~20k, so it decodes at a deeper context than the 2-tool
  prompt. The speed loss cannot be split between "tools" and "depth".
- The t2b repeat reused the cached prefix (evaluated 516) and matched t2 (43.7 vs 43.8).

## Verdict

Reading only. No failure with 107 tools (server alive, normal answers). Speed difference is confounded by depth.

## Toolbox

- Method: an agent probe with a large tool list (a real agent harness sends ~100 tools). Control the total prompt
  length when you compare tool counts; otherwise the result measures depth.
- Transfers: tool-list size adds tens of thousands of tokens to every request; on an 8 GB card that moves the prompt
  past the VRAM line.
