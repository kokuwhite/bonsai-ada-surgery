## Question

With the pool on, does the failure depend on CUDA graph replay, on the reduced draft ubatch, or on patch 0041? What
token does the model emit when it fails?

## Deviations, incidents, void runs

- Contradiction to note: the notebook reports draftub_default as "0/3 (decode 13.7?)". The receipt shows the three
  answers were 5, 4 and 4 tokens long (not 400), with acceptance 0.250. These are not 1-token answers, but they are
  not normal answers either; the arm most likely also failed (early end of turn after a few tokens). The 1-token
  counter did not catch it.
- The plan said "draft ubatch unset"; the script set LLAMA_MTP_DRAFT_UBATCH=512 (the value taken as the default).
- pool_control passed 0/3, while every P64 pool-on arm failed 3/3: the failure is intermittent.

## Verdict

Reading only. Graph replay is not the cause (graphs off still fails). The race is intermittent. The wrong output is an
early end-of-turn token with high probability: a wrong model state.

## Toolbox

- Method: when a model answers "nothing", read the logprobs of the first token. A confident end-of-turn means the
  hidden state is wrong (memory race, stale cache), not a sampler problem.
- Count "short answers" (n < expected) as well as n == 1; a race can also truncate after a few tokens.
- Transfers: intermittent races need repeated server starts per arm (P69 used 6 per engine).
