## Question

After the move, is the card the same: kernel tests, decode, temperature, PCIe link, free VRAM?

## Why

The PC was moved between 2026-10-11 11:50 and 2026-10-13 10:54. A card that is badly seated, has a cooling change or
runs on a narrower PCIe link would change every later number. P109 and P108 waited for this check.

## Plan and gate

Script header: "Same binary, launcher and request mix as P96 (bundle-20261010, main 262k test launcher, layer off),
sweep 4k/32k/64k. Gate (declared here, before the run): kernel tests pass; decode within 3 % of P96 (51.5 / 51.3 /
34.4); 0 one-token; trace min free >= 60 MiB; max GPU temperature <= 80 C. Else stop and tell Cary (seating, cooling,
PCIe link)."

## Method

test-backend-ops ADD / RMS_NORM / FLASH_ATTN_EXT on the bundle bin. One run_arm.sh sweep, quick_tps 4000 -> 32000 ->
64000 (P96's request mix: code, prose, bash per depth). An nvidia-smi trace every 10 s through the arm: free MiB,
temperature, graphics and memory clock, power, PCIe generation and width.

## Deviations, incidents, void runs

- Gate as written: 4k +2.7 % pass; 32k -10.5 % FAIL; 64k +9.3 % is also outside "within 3 %", in the faster
  direction (the notebook lists it without a grade). Tests, 0 one-token, trace min free (100 >= 60) and max
  temperature (67 <= 80) pass.
- The summary line "trace min free -4186609 MiB" is wrong. The script's awk compared the free field as a string after
  sub(), so "7787" > "4000000" was true and the wrap correction subtracted 4,194,304 from normal values (7,695 -
  4,194,304 = -4,186,609). Fixed by hand: min free is 100 MiB. The script in queue/done (and in scripts/queue/) has
  the fix (v+=0) added after the run; P113 and later scripts use it.
- The VRAM line is 62,464 cells, not P96's 57,600: idle was 220 MiB here vs 302 MiB at P96's start. 4,864 cells x
  18,432 B = 85.5 MiB, the idle difference. So the 64k item mix ran with more cells in VRAM than in P96.

## Verdict

No change from the move. Notebook: "P110 matches both [P85, P88] within 1 % at 32k / 64k. P96 (32k 53.5 / 52.1 / 48.4,
64k 34.4) is the outlier in both directions (P94: lookup drafter history moves these items). Verdict: no change from
the move; the reference should have been the P85 / P88 / P96 range, not P96 alone (lesson: a smoke gate needs a
reference range, not one run)." Temperature and PCIe link are normal. The queue went on (P109 started 11:05:56).

## Toolbox (for the next model)

- Method: after any physical change to the rig (move, reseat, new cooling), run a short smoke on a released binary
  before any experiment: kernel tests, a 3-depth sweep, and a 10 s trace of free VRAM, temperature and PCIe link.
- Method: gate a smoke against the range of several earlier runs of the same item mix, not one run. With lookup
  drafting, single items move by 10 % or more between runs (P94).
- Pitfall: in awk, a field changed by sub() is a string; add 0 before any numeric compare.
- Pitfall: free VRAM at idle moves the auto-sized line (~57 cells per MiB at q4_0); log the line in every arm before
  you compare depths past it.
