## Question

Does the published bundle-20261011 zip pass the 8 GB release gates on the RTX 2060 SUPER?

## Why

The 4070 session shipped bundle-20261011 (patch 0053: CUDA graphs off only for graphs whose attention reads the host
tail) after P103 / P103b passed on 8 GB. Every bundle gets a release check on the downloaded asset on this card.

## Plan and gate

Notebook: "P113 (queue 69g3, after P111 / P112; from the P96 script, gate in its header): sha256; ADD / RMS_NORM /
FLASH_ATTN_EXT; sweep 4k-128k (each >= the P85/P88/P96/P110 minimum - 3 %; 128k >= 14.3 = P96, since 0053 helps past
the line); fresh 60k x2; lookup_ab d0 / d64000 (texts vs P96 reported, not gated: P94); 0 one-token; trace min free
>= 60 MiB. Fixed in the copy: the trace awk now converts the field to a number (the P110 string-compare bug)."

Script header: "Gate (declared here, before the run): sha256 match; ADD / RMS_NORM / FLASH_ATTN_EXT all pass; decode
within the P85 / P88 / P96 / P110 range at 4k-128k minus 3 % (4k >= 49.3, 32k >= 44.4, 64k >= 33.4, 96k >= 19.4, 128k
>= 13.9) and 128k >= P96 (14.3) since 0053 helps past the line; 0 one-token; trace min free >= 60 MiB; lookup_ab texts
compared with P96 (report, no gate: history differs, P94)."

## Method

gh release download bundle-20261011 (bonsai-bundle-win-x64.zip), Get-FileHash SHA256, Expand-Archive. test-backend-ops
ADD / RMS_NORM / FLASH_ATTN_EXT on the bundle bin. run_arm.sh sweep 4000 -> 32000 -> 64000 -> 96000 -> 128000 (one
server, P96's item mix) with a 10 s free-VRAM trace; two fresh servers with one 60k prompt each, each with a trace;
then a server via serve.ps1 and lookup_ab.py at depth 0 and 64000 (22 items: 4 quote, 3 plain, 4 edit per depth).

## Deviations, incidents, void runs

- The VRAM line is 62,464 cells, as in P110 and not P96's 57,600: idle was 217 MiB here vs 302 MiB at P96's start
  (4,864 cells x 18,432 B = 85.5 MiB). So the gains over P96 at 64k-128k come from patch 0053 and from 4,864 more cells
  in VRAM together. The like-for-like reference at the same line is P110 (bundle-20261010): 52.9 / 45.9 / 37.6 at 4k /
  32k / 64k vs 53.9 / 47.9 / 38.0 here. No same-line reference exists at 96k / 128k. The #22 post reads 96k +37 % and
  128k +18 % "as P103 predicted for patch 0053"; part of that gain is the line.
- Script header arithmetic: the 128k floor 13.9 is P96's 14.3 minus 3 %; the range minimum at 128k is 14.1 (P85, P88),
  minus 3 % = 13.7. No effect: 16.9 passes both, and the separate 128k >= 14.3 gate.
- 32k (47.9) is below P96 (51.3) and inside the P85 / P88 / P110 spread (45.8-46.2): P110 showed P96's 32k is the
  outlier.
