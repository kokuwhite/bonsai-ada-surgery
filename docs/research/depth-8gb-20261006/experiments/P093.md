## Question

Does GGML_CUDA_FA_CHUNK=32768 change depth-0 texts, where no op should have more than 32,768 KV cells?

## Why

P91 depth-0 plain texts differed from P85. P92 showed the chunk binary with the switch off = the engine without the
patch. P93 tests the switch itself with the PR #19 launcher. Notebook: "P93 investigating before the bundle".

## Plan and gate

No separate plan entry. Script header: "P93: does GGML_CUDA_FA_CHUNK=32768 change depth-0 texts (where no op should
have > 32,768 KV cells)? Same launcher (PR #19 branch copy), same bin; off vs on, twice each; server log at
verbosity 4 for the chunk line." Implied gate: 11/11 same.

## Method

Four servers in order off, on, off2, on2. lookup_ab.py depth 0 (11 items). Text shas compared with off_d0. grep of
the server log for the chunk line ("FA_CHUNK|chunks of") and for n_kv values.

## Deviations, incidents, void runs

- The chunk-line and n_kv greps returned nothing in all four arms (empty *.chunkline.txt and *.nkv.txt), also at
  LLAMA_LOG_VERBOSITY=4. Engagement of the chunk path at depth 0 could not be read from the log (not expected
  there anyway).

## Verdict

Notebook: "P93: chunk off/on/off/on with the PR #19 launcher: 11/11 identical in all four. Cross-run: P85 = P88 (Oct
9); P91 = P92 = P93 (Oct 10); the two groups differ in the 3 plain items only; bin-pmask with the same launcher gave
the Oct 9 texts on Oct 9 and the Oct 10 texts on Oct 10. Not the engine, not the switch. No date in the chat
template. Candidate: prompt-cache reuse of the shared template prefix (restore vs recompute -> different batch
split) depending on memory state at start."

## Corrections later

P94 tested the candidate: the prompt cache is not the cause (texts change between pass 1 and pass 2 with the cache
on and off). The cause is state carried across requests in one server (most likely the lookup n-gram drafter's
history).

## What it changed

PR #19 cleared: "Posted on #19: bundle can go." bundle-20261010 shipped with 0051-0052 on for 8 GB.
Lesson recorded: "compare texts only within one session window (same day, alternated arms)".

## Toolbox (for the next model)

- Method: alternate off / on / off / on in one window; one pair is not enough to separate a switch effect from drift.
- Transfers: a switch whose code path cannot run at a given depth must give identical texts there; if it does not,
  look for state outside the engine (request history, caches) before blaming the kernel.
