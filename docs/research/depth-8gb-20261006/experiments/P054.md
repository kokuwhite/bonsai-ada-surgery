## Question

Does the tail-2 one-token bug (P18) reproduce on the newest engine, and only with the prompt-cache restore path (the
stale rollback plane hypothesis from P35)?

## Why

P35 code read: stale rollback planes after a prompt-cache restore (~40 % confidence). Backlog item 6.

## Plan and gate (as frozen before the result)

"bin-lookup, main launcher test copy, drafting preset, lookup off. quick_tps 4k -> 16k -> 32k (it sends "Say hi."
between depths, P18 sequence). Arms x3 alternated: tail 2 N=40,960 cache on / tail 2 N=40,960 LLAMA_ARG_CACHE_RAM=0 /
tail 1 N=51,200. Reading: one-token answers per arm. Cache-on only -> the prompt-cache restore path (stale ring plane
hypothesis); none -> not reproduced on this engine (record, keep tail 1)."

## Method

Three rounds of the three arms; each run: quick_tps code / prose / bash at 4k, 16k, 32k (9 answers per run, 81 in
total).

Acceptance 0.798 in every run. The restore path was exercised: with the cache on, the 16k and 32k code prompts
evaluated 12,504 and 16,524 tokens (the rest restored); with `LLAMA_ARG_CACHE_RAM=0` they evaluated 16,036 and 32,044
(full re-prefill).

## Deviations, incidents, void runs

None.

## Verdict

"0 of 81 answers (tail 2 with and without LLAMA_ARG_CACHE_RAM, tail 1; 3 rounds each, 4k -> 16k -> 32k with "Say
hi."). The P18 failures (2026-10-07) ran with GGML_CUDA_SHARED_POOL=1 (bin-p12 C2 config). Most likely the same pool
race (fixed: pool off in the preset, patch 0045). The stale-plane hypothesis is not needed; the open tail-2 item is
closed unless it shows again with the pool off."

## Corrections later

None. docs/8GB.md (PR #12): "the tail-2 one-token answers and the packed-mask run both had the shared CUDA pool on.
With the pool off, tail 2: 0 of 81."

## What it changed

The tail-2 bug item closed; the P35 stale-plane hypothesis and the proposed rs_valid detector dropped.

## Toolbox (for the next model)

- Method: repeat a rare bug with the suspected path on and off (here the prompt cache), and log evidence that the path
  ran (evaluated-token counts).
- Transfers: when a later bug (the shared pool race) explains an earlier one, re-run the earlier repro with the later
  fix before you build a fix for the old hypothesis.
