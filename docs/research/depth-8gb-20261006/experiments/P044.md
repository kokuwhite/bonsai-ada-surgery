## Question

On Turing, is 1-query decode faster with or without the flash-attention MMA route, per K/V type and depth?

## Why

sb32445 asked for Turing data (#317 / #307).

## Plan and gate (as frozen before the result)

"bin-rc3, plain model, no head, -c 32768, GGML_CUDA_FA_MMA_DECODE_MIN_KV=0 (never) vs default 256, K/V q4_0 and q8_0,
4k/16k, alternated x2. Reading: decode delta per K/V type and depth; texts compared. Reply on #317 with the table."

## Method

Order per round: q4_0 mma, q4_0 nomma, q8_0 mma, q8_0 nomma; two rounds. Server restarted per run; quick_tps at 4k
and 16k.

## Results

| K/V | route | 4k decode r1 / r2 | 16k decode r1 / r2 | code prefill 4k (r1) | free at load |
| --- | --- | --- | --- | --- | --- |
| q4_0 | MMA (default) | 43.5 / 43.8 | 38.9 / 39.0 | 412.0 | 1,331 |
| q4_0 | no MMA | 41.2 / 41.3 | 32.9 / 32.9 | 411.5 | 1,331 |
| q8_0 | MMA (default) | 43.7 / 43.7 | 38.9 / 38.9 | 408.2 | 819 |
| q8_0 | no MMA | 42.2 / 42.2 | 34.3 / 34.2 | 408.9 | 819 |

Gain of the MMA route: q4_0 +6 % (4k) / +18 % (16k); q8_0 +4 % / +14 % (notebook). Text compare: not reported in the
notebook entry.
