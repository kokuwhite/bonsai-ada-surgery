## Question

What do decode and prefill look like from 4k to 126k in the shipped 131k window, in both modes? (Cary asked whether
it "feels great at the end of the window".)

## Why

"Never measured past 60k in the drafting mode."

## Plan and gate (as frozen before the result)

"Merged launcher (7882d0f copy), preset auto, bin-rc3, stock clocks, layer off. quick_tps depths 4k / 32k / 64k / 96k /
126k (each extends the previous prompt). Also the long-context mode. Reading (no gate - this is the measurement Cary
asked for): decode and prefill per depth, free VRAM, one-token answers. "Feels great at the end of the window" is
answered by the 126k decode number and the time to extend the prompt there."

## Method

run_arm.sh per mode through the launcher copy; quick_tps code / prose / bash at each depth (the code prompt extends the
context; prose and bash reuse the prefix and evaluate ~512 / ~1,024 tokens).

## Verdict

P40 (as written then): "Past the VRAM line (~54-59k) decode falls with depth: PCIe 3.0 reads of the host tail. 126k =
11.3 tok/s (drafting)." "Drafting mode through the launcher is not affected (51.3 = P34 50.9)."
P40c: "Drafting numbers equal the old-engine run: the verify step is 2 columns, and #325 changes only the 1-column
path. Long mode 43.9 at 4k = P34. Past the VRAM line decode is PCIe-bound (126k: 11.3)."

Receipt note on P40c vs P40: drafting decode matches, but drafting prefill does not at 32k (331.1 vs 291.4, +14 %);
long-mode prefill differs at 32k (351.1 vs 308.9) and 64k (254.5 vs 200.6). "Drafting numbers equal" holds for decode.

## Toolbox (for the next model)

- Method: extend one prompt step by step to each depth; read decode and the TTFT of each extension.
- Model-specific: past the VRAM line (~54-59k positions on this card) every decode step reads the host tail over
  PCIe 3.0: 30.7 at 64k, 16.3 at 96k, 11.3 at 126k (drafting).
- Transfers: print the engine path and version in every receipt. A "launcher regression" that a bisect cannot localize
  can be the binary itself. Check that the launcher honors the variable you set (here BONSAI_BIN was ignored).
