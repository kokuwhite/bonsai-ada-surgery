## Question

Does the shipped 8 GB config hold one long agent-style conversation deep into the 262k window: no failures, no
one-token answers, no memory errors, and turns that take seconds to minutes (checkpoints), not a full re-read?

## Why

P96 checked bundle-20261010 to 128k. Users with long-document or agent work go deeper. P86b gave the synthetic decode
at 250k (5.7 tok/s); a real multi-turn session at depth was not yet run.

## Plan and gate

Notebook: "P99 (plan, queue 63): deep agent soak on bundle-20261010 (main launcher): ~150k real-source start + 25
turns x ~2.5k tokens; per-turn wall/pp/tg/one-token, server private, VRAM trace. Gates: 26/26 OK, 0 one-token, server
alive, trace min >= 60 MiB, no bad_alloc / CUDA error; per-turn wall reported (checkpoints should keep turns at
seconds-to-a-minute, not a full re-read)."

## Method

deep_soak.py: one conversation. Turn 0: a real Python stdlib source prefix (target 150,000 tokens at 3.2 characters
per token; files *.py then */*.py in order). Each later turn appends the previous answer and a new user message with
~2,500 tokens (target) of further source and a question about the new file. Per turn: prompt tokens, new tokens
processed, wall, prefill and decode tok/s, completion tokens, one-token flag, server private MiB and free VRAM after
the turn. nvidia-smi free VRAM every 10 s. After the run: /health and a grep of the err.log for "cache size limit",
"bad alloc", "CUDA error".

## Deviations, incidents, void runs

- Planned ~150k start and 25 turns of ~2.5k tokens; got a 132,882-token start (characters-per-token guess high) and
  new tokens per turn of 2,607-21,972 (the previous answer plus the next source chunk, with whole files). The window
  filled at turn 18 (HTTP 400: context full), so 18 turns ran, not 26. The gate "26/26 OK" was read as 18/18 plus the
  expected end.

## Toolbox (for the next model)

- Method: a deep multi-turn soak on real text, one conversation to the window end, with per-turn speed, process
  memory and a VRAM trace, plus a check that each answer is about the newest content.
- Model-specific: turn walls stay at minutes because the server restores context checkpoints (recurrent state of the
  48 GDN layers) and only processes the new tokens.
- Transfers: soak gates (no failures, no one-token answers, memory flat or smooth, VRAM floor) apply to any model and
  card.
