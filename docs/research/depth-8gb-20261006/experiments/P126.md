## Question

P126: does the published bundle-20261013 zip pass the 8 GB release gates on the RTX 2060 SUPER? P126b: is P126's
-4 to -7 % at 64k-128k the release or the session?

## Why

prefill with BF16 MMA), which must skip on sm_75 (P116, P116b). It is also the new reference for the sparse gates
(4070 on #21, 01:57Z).

## Deviations, incidents, void runs

- P126's first run was cut by the power cut (events E32). The notebook says the sweep had reached "~64k"; the
  receipts show 4k-96k complete and the 128k prefill at 94 %. The job was rerun from the start (zip and x/ already on
  disk).
- P126b's first run was cut by the system crash (events E34) during the fourth server. Its three complete rounds give
  the same picture as the rerun at a higher level. The interrupted servers ended with 55 MiB free (below the usual 60
  MiB gate; P126b had no free-VRAM gate).
- The notebook and the #40 post put the crash at 23:40; the 1013 r2 server started at 23:43:58 and wrote its 96k
  result at 23:52:21. The crash was at ~23:56 (events E34).
- The #40 post says P126 ran "with Windows servicing (TiWorker) active in the background". The System event log
  (read for this record) has no Windows Update or servicing event between 21:51:26 and 23:46:06; servicing started at
  23:46, after P126 (21:59-22:40) and during the P126b first run. So the P126 gap is a session effect, but its cause is
  not shown.
- Observation (from the receipts, not a gate): in every 64k-128k sweep of this range, runs whose server loaded at
  7,523-7,524 MiB read 38.0-38.3 at 64k (P113, P126 first run, P123 off_r2, P126b first run), and runs that loaded at
  7,460-7,464 MiB read 35.1-36.2 (P126 rerun, P123 off_r1, P126b rerun). The launcher output of P123 off_r1 and off_r2
  differs only in the line (256 cells) and free VRAM at start. What sets the 63 MiB is not found.
- Launcher line in P126 rerun: 61,696; P126b rerun: 61,184-61,440; P113: 62,464.

## Toolbox (for the next model)

- Method: never gate a release on a number from another session. Run the old and the new release alternated in one
  session at the depths past the line; session-to-session moves here were ~5 % at 64k.
- Method: when a run is cut, keep its partial receipts in a separate folder; they can carry a reading (here the
  pre-cut P126 sweep equals P113).
- Pitfall: the time in Windows event 6008 ("previous shutdown at ...") is not the crash time; use the last receipt or
  log line.
