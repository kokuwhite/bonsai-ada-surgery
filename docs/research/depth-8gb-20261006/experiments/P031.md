## Question

Does the 8 GB drafting mode (q4_0 K/V, MTP head, draft 1) keep the coding quality of the 12 GB setup?

## Why

Cary: "113k is fine as long as its good, consistent quality" (after P30). The 12 GB receipt with the same harness:
159/164 raw, 160 on a neutral rerun, 161 on q8_0 at 262k.

## Plan and gate (as frozen before the result)

"Same harness as the 12 GB receipt (bench/humaneval_run.py --arm medium, temp 0, max tokens 20480 ...). Gate, written
before the run: >= 157/164 (12 GB 159-161; 4-seed deltas of 1-2 are noise per the repo) and no one-token / empty
answers. Below 157 -> q4_0 K/V or drafting costs quality on this card; investigate before shipping."

## Method

164 HumanEval problems, one greedy run (temperature 0), medium thinking, max tokens 20,480, layer off. The harness
runs each completion's code against the tests.

mode and 67 as whole code; no empty code block. Total completion tokens 159,013.

- P32 (q8_0 K/V): 159/164. Reading: q4_0 costs ~2 of 164, at the edge of noise; q4_0 stays.
- P53 (same drafting preset + lookup drafting, bin-lookup, no shared pool): 158/164. Fillers on 2026-10-09 (06:05,

## What it changed

docs/8GB.md states the score (q4_0 157/164) next to q8_0 (P32). The 8 GB preset kept q4_0.

## Toolbox (for the next model)

- Method: one greedy HumanEval 164 run with a gate frozen from the reference card's spread (here 157 = 12 GB low
  minus 2). Then a second arm that changes one factor (P32) to attribute the gap.
- Model-specific: the scores and the failing set (32, 40, 47, 92, 116, 145, 160).
- Transfers: a single-run coding score has a noise band of 1-2 problems at 164. Use a boundary gate and a paired
  follow-up arm, not one number.
