## Question

Is there a better launch shape for the PTQ1_0 1/2-column mat-vec on Turing (72 % of a decode step)? Does
GGML_CUDA_GRAPH_OPT=1 help?

## Why

Cary: "Turing is a generation everyone moved past; find the leftover." The kernel uses 4 rows per item and
launch_bounds(128, 4), chosen on Ada/Ampere.

## Plan and gate

Notebook: "prism-tune 3200e3761 (on 5251968b0): runtime GGML_PTQ1_PT_TUNE=RxM, R in {2,4,8}, M in {2,4,6,8};
per-row arithmetic unchanged (expect identical bits). Sweep: test-backend-ops perf MUL_MAT ptq1_0 at n=1 and n=2 for the
7 decode shapes, weighted by uses per token (gate/up 5120x17408 x128, down 17408x5120 x64, qkv 10240 x48, z 6144 x48,
ssm_out 6144->5120 x48, q 12288 x16, o x16) -> us per token per combo. Plus GGML_CUDA_GRAPH_OPT=1 vs 0, plain raw
server, quick_tps 4k x2 + greedy texts. Gate: a combo >= 3 % faster weighted (n=1 or n=2) -> end-to-end A/B (P79) and,
if it holds, a Turing default."

## Method

For each of 12 combos and n = 1, 2: test-backend-ops perf, parse us/run per (m, k) shape, weight by uses per token.
Then 4 raw-server arms alternated: GRAPH_OPT 0, 1, 0, 1 (quick_tps at 4000).

  282 MiB ..."); the server arm could not start.

  plan has no own key, so its 16 uses per token are not in the weighted sum. The ranking of combos is unlikely to
  change (the default is within 0.6 % of the best on every shape listed).
- The plan's "greedy texts" for GRAPH_OPT were not taken (only quick_tps).

## Toolbox

- Method: runtime-tunable launch parameters + test-backend-ops perf per decode shape, weighted by uses per token,
  give a whole-model estimate in minutes without serving.
- Model-specific: the shape list and weights (gate/up x128, down x64, qkv/z/ssm_out x48, q/o x16) are Bonsai 27B's
  (48 GDN + 16 attention layers, 64 FFNs). PTQ1_0 at 1.75 bpw.
- Transfers: compute achieved bandwidth (bytes / time) before tuning; at 80 % of peak, launch shape cannot give much.
- Build lesson: a build script must check that the binaries exist; cicc can crash under RAM pressure and still exit 0.
