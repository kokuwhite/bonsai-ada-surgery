## Question

Past the VRAM line each decode step is PCIe-bound. Are extra verify columns (tail 2-4) nearly free there, so that a
longer tail draft pays at 96k-126k even after it costs positions in VRAM?

## Why

"12 GB runs tail 4: past the line a step is PCIe-bound and extra verify columns are nearly free. On 8 GB each tail step
adds a 149.6 MiB recurrent plane (~10k q4_0 positions)."

## Plan and gate (as frozen before the result)

"Arms (draft 1 below the line, bin-rc3, launcher copy, layer off): tail 1 N=51,200 / tail 2 N=40,960 / tail 3
N=30,720 / tail 4 N=20,480. Depths 4k/32k/64k/96k/126k. Gates: a tail >1 arm beats tail 1 at 96k and 126k by > 25 %,
loses < 10 % at 32k, no one-token answers, free >= 80 MiB. Pass -> a deep-end option (or a depth-switched default)
with this receipt. Watch: tail 2 one-token bug (P18)."

## Method

One server per arm, quick_tps code / prose / bash at each depth (each step extends the code prompt).

## Toolbox (for the next model)

- Lever: tail draft count past the VRAM line on a hybrid model with recurrent rollback planes.
- Model-specific: 149.6 MiB per extra plane; acceptance falls 0.798 -> 0.748 -> 0.661 -> 0.601 with tail 1 -> 4.
- Transfers: on 8 GB, a lever that costs positions in VRAM moves the PCIe cliff closer; it loses most at mid depth
  (32k-64k) and gains little at the far end. On larger cards (12 GB) the same lever can pay.
