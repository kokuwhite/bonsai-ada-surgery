## Question

P116: patch 0054 (a port of ggml-org/llama.cpp#29353) runs the 48 GDN layers in prefill with BF16 MMA. Turing has no
BF16 MMA. Does the patched engine skip the new path on sm_75, keep op tests green, and keep 32k prefill and decode
equal to 0053? P116b: after the 4070 applied the P116 code note, does the merged commit still pass, with a clean
"skipped" line?

## Why

The 4070 asked on #21 (21:35Z) for a sm_75 check of PR #40 before merge. Code reading on the 2060 side (notebook):
"on sm_75 it allocates temporaries (and activates raw gates) before ggml_cuda_gdn_mma_launch fails -> logs 'not taken
(shape or device)' (not 'skipped'); small wasted work per GDN prefill op; the 32k gate covers it."

## Plan and gate

P116 script header: "Gates (from the 4070 request, declared here before the run): 1. test-backend-ops -o
GATED_DELTA_NET passes on bin-0054. 2. the 0054 server log has a 'chunked GDN prefill (MMA) skipped' or '... not
taken' line and NO 'engaged' line. 3. 32k on the 8 GB launcher: prefill and decode of 0054 equal 0053 within noise
(|diff| <= 3 %, alternated twice)."

P116b script header: "Gates (declared here, before the run): GATED_DELTA_NET op tests pass; the server log has the
'skipped: device cc' line and no 'not taken' / 'engaged' line; 32k decode and prefill within 3 % of P116 (0054 r1/r2:
prefill 343.9 / 344.0, decode 44.9 / 44.7) and of the bundle-20261011 arm run here."

## Method

P116: build e63ce36d9 (during P114's quality phase, which is not CPU-sensitive), test-backend-ops -o GATED_DELTA_NET,
then four servers alternated: 0053 r1 (16:58), 0054 r1 (17:01), 0053 r2 (17:03), 0054 r2 (17:06), each with quick_tps
at 32000 (code, prose, bash). Count the GDN lines in each server log. P116b: incremental build of de873117e inside the
job (so that P115's 245k arms ran with no build load), op tests, then one bundle-20261011 server (18:28) and one
de873117e server (18:30) at 32000.

## Toolbox (for the next model)

- Method: for a patch that must not run on an arch, gate on its own log line ("skipped" / "not taken" / "engaged"),
  plus op tests and an alternated A/B at one depth.

  wording ("not taken" vs "skipped") also showed.
