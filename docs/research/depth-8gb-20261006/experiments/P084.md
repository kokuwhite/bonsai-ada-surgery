## Question

With the three VRAM levers together (packed mask, pool, partial staging), does a 262k window beat the shipped 131k
preset at every depth?

## Why

P81: partial staging works but D lost 7,168 cells to the f16 mask. P82: packed mask frees 108 MiB at 131k. P83: pool
frees ~51 MiB.

## Plan and gate

Notebook: "bin-pmask (has 0045). N pinned 59,904 for both windows (= 50,176 + ~6.7k packed + 2,048 pool + 1k from the
margin). Expected trace min ~115-125 MiB. Arms: A preset (control); H131 131k packed + pool, N 59,904 (whole-tail
staging); H262 262k packed + pool, N 59,904, staging frac 0.308594 (80,896 staged cells: prefill fast to ~141k);
sweep 4k/32k/64k/96k/128k (+160k on H262), VRAM trace; fresh 60k x2 on H262.
Gates for the 262k 8 GB default: H262 decode >= A - 1 % at 4k/32k and >= A at 64k-128k; prose prefill within 10 % of A
up to 128k; trace min >= 60 MiB; 0 one-token. Pass -> launcher constants (packed / pool / stage terms), PRs: engine
patches (partial staging, packed mask on our stack with the race note), launcher 262k default on 8 GB."

## Method

A, H131, H262 sweeps (one server each), then 2 servers H262 with a fresh 60k prompt; VRAM trace every 10 s.

## Deviations, incidents, void runs

- N was pinned (59,904) in this test; the auto-sized launcher came in P85 (N 58,880).
- Arm A here measured 51.0 at 4k (other A runs: 51.8); the +1.4 % at 4k is partly this lower A reading.

## Verdict

All gates pass. Notebook: "Decision: 262k becomes the 8 GB default with engine patches 0047 (partial staging),
0048/0049 (packed mask) and the shared pool on for 8 GB. Next: launcher (auto-sized, not pinned) + real-launcher
check, then PRs."

## Corrections later

- P85 (launcher as users get it, N 58,880): within 1.7 % of H262.
- P86 / P86b / P89: the deep end past N+S (~141k): bulk prefill there is ~3x slower than staged (fixed by chunked
  prefill, P89, PR #19).

## What it changed

PR #13: 262k 8 GB default + patches 0047-0049 + receipts/262k_8gb. Fillers moved to the 262k test launcher.

## Toolbox

- Combined lever: on an 8 GB card the KV line moved from 50,176 to 59,904 cells (+19 %) by removing fixed VRAM costs
  (mask, pool, staging per window). Decode at 64k +24 %, and the window doubled.
- Method: when levers are independent, run them combined against the shipped default, with a strict gate per depth.
- Transfers: count every fixed VRAM item that scales with the window (mask, staging) or with contexts (pools) before
  you size the KV line.
