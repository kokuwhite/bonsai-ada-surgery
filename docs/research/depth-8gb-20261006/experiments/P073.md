## Question

Does the PR #11 launcher set checkpoint-every-nt 8192 by itself on an engine that has the flag, and does it give the
P71 speedup with identical text?

## Why

P71: patch 0046 is correct. PR #11 ships it with the 8 GB preset setting 8192.

## Plan and gate

Notebook: "Build prism-0046 (5251968b0 on 142d5105d) sm_75 -> bin-0046. Launcher = PR #11 branch copy
(start-server-pr11.ps1). Arm A: preset auto (must print / set LLAMA_ARG_CHECKPOINT_EVERY_NT=8192 because the engine
has the flag). Arm B: same with BONSAI_CKPT_EVERY=0. lookup_ab.py at 64000 each. Gates: A sets 8192 by itself; A text =
B text for all 11 items; A wall per request after the first < 50 % of B; 0 one-token; launcher output and server RAM
recorded."

## Method

Arm A then arm B, one server each, lookup_ab.py at depth 64000 (11 items). The server command line was read from
Win32_Process; the server working set sampled every 20 s.

## Deviations, incidents, void runs

- auto.restores.txt and off.restores.txt both read 0: the grep for "restored context checkpoint" in the server log
  found nothing (the server log is at default verbosity; P71 needed verbosity 4 to see restore lines). The wall times
  show the restores.
- The two arms have different VRAM lines (49,408 vs 48,896) because the launcher sizes N from the free VRAM at start.
- P55 (another queued job) failed in this window: "model path lost its file name (backslash escaping)"; requeued as
  35-p55b (see P055 and the events file).

## Verdict

All gates pass: A sets 8192 (wall 60.5 s vs 227.0 s = 27 %, < 50 %); 11/11 same text; 0 one-token; RAM recorded
(+499 MiB working set max for the checkpoints).

## Toolbox

- Lever: in-message checkpoints. On a hybrid model the first request after a long shared prefix that diverges inside a
  message drops from a full re-prefill to a restore plus a short tail.
- Cost: host RAM (here +0.5 GB working set at 64k; up to 32 checkpoints x ~168 MiB per slot). On 16 GB RAM machines
  this needs a budget (issue #16, PR #18).
- Method: check that the launcher really sets the feature (end to end) before you claim it ships.
