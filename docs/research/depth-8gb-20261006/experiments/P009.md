## Question

Is core +150 at 215 W with fan 100% stable, cool enough and exact over 10 minutes, so it can be the rig baseline? Cary
wants the card overclocked.

## Why

P004: +150 gave +4.9% but the card reached 87 C during a short sweep.

## Plan and gate

P9 plan: "Profile (Afterburner slot 4, rewritten): PowerLimit 122 (215 W), fan fixed 100%, core +150, memory +0 (P3:
memory does nothing for decode). Fallback slot 3: same with core +100. Serve: B config (q4_0, N=38656, no head, layer
off) on bin-turing (the P8 build). Load: p9_soak.py, 10 minutes continuous, alternating 4k / 16k greedy requests of 300
tokens, logging decode, core clock, temperature and power per request; then one greedy text pair at stock vs OC."
Gates written before the run (quoted):
- "max GPU temperature < 85 C (max operating 89 C);"
- "decode of the last 2 minutes within 3% of the first 2 minutes at each depth (no thermal or demotion slide);"
- "greedy texts at OC byte-identical to the same serve at stock (core offset errors would show as divergence);"
- "no driver reset. Pass -> slot 4 becomes the rig baseline and every later receipt names it; fail at +150 -> repeat
  with slot 3 (+100); fail there -> stock stays."

P9b had no plan entry. The chain script comment: "P9b (OC +150 re-soak with desk fans, fan 100%)". The P9 result had
said "Next per plan: slot 3 (+100) soak, queued behind P10"; P9b instead repeated +150 with the new cooling.

## Method

p9_soak.py warms the 4k and 16k fillers, then alternates requests: 4k and 16k depth, prompts "merges overlapping
intervals, with tests" (code) and "how a heat pump works in winter" (prose), 300 tokens, greedy. A thread samples
`clocks.gr, temperature.gpu, power.draw, clocks_throttle_reasons.active` every second. Stock: 120 s; OC: 600 s on the
same server (slot switched live). Identity: every OC text vs the stock text of the same (depth, prompt).
P9b: same, through p9b_p11_chain.sh; slot changes go through slot 3 first so slot 5 really applies.

## Toolbox

- Method: a 10-minute soak with per-request telemetry (clock, temperature, power, throttle reason) and byte-identity
  against a stock reference of the same (depth, prompt) key. Record throttle reasons: 0x4 (software power cap) and 0x20
  (software thermal slowdown) explain speed drift.
- Lesson: identity soaks on hybrid models need a cache-controlled design; a prompt-cache restore can change prefill
  splits and so greedy text, and that confounds a compute-error test.
- Card-specific: a stock 2060 SUPER is power-capped at 175 W during decode. +150 core at 215 W gives +1.6-4.1%; cooling
  sets whether it is usable.
