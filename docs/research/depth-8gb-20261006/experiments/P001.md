## Question

What does the plain model cost in VRAM on this card before any KV cell is placed (the "fixed cost")? Does the launcher's
constant match it?

## Why

First serve on the 8 GB rig. The rig header (notebook line 3) measured idle used 783 MiB and free 7,224 MiB with the
desktop on the card. The launcher model for the plain file without a draft is
`Fixed = file_MiB - 265 + 150 + 400 + 300` (~6,225 MiB). With free 7,224 MiB and margin 1,300 MiB the budget is
negative, so auto-sizing throws (floor 16,384 cells). The handoff table assumed ~5,770 MiB fixed for no-draft. The
launcher formula subtracts only ~43 MiB of draft cells for SPEC=0.

## Plan and gate

Arms: plain PTQ1_0 file, BONSAI_SPEC=0, q8_0, BONSAI_CTX=131072, BONSAI_KV_VRAM_CELLS pinned at 16384, then 8192 if
16384 does not load. Read nvidia-smi used at idle after load. Solve
`Fixed = used_at_load - before_used - N*CellBytes - (Ctx-N)*CellBytes/16`.

Gates written before the run (quoted):
- "the server loads and answers one greedy request;"
- "measured fixed cost is reported to the MiB; if it differs from the launcher's 6,225 by more than 200 MiB, the
  launcher constant is wrong for this card and gets corrected before any auto-sized run;"
- "no shared-memory (demotion) growth visible in Task Manager "Shared GPU memory" during load."

## Method

One serve with N=16384 pinned (the 8192 fallback was not needed). nvidia-smi read before load and after load. One
greedy request "17*23". Task Manager "Shared GPU memory" read during load.

## Results

| item | value |
| --- | --- |
| nvidia-smi used before load (idle) | 838 MiB |
| used after load | 7,494 MiB (server 6,656 MiB) |
| used / free after a request | 7,506 / 501 MiB |
| KV head in VRAM | 16384 x 34,816 B = 544 MiB |
| staging (host-tail window) | 114688 x 2,176 B = 238 MiB |
| fixed cost, measured | **5,874 MiB** |
| fixed cost, launcher model | 6,256 MiB |
| greedy "17*23" | 391 |
| Shared GPU memory | 4,008 MiB = pinned host tail (3,808 MiB) + host buffers, not spill |

Gates: loads and answers PASS. Fixed cost off by 382 MiB (> 200) FAIL: the launcher constant needs a correction for this
card; BONSAI_KV_VRAM_CELLS stays pinned until then. Shared growth: none beyond the pinned tail, PASS.

## Deviations, incidents, void runs

- The plan text gives the launcher model as "~6,225 MiB"; the result gives "launcher model 6,256" and computes the
  382 MiB gap from 6,256. The notebook does not say which value is correct. Both are kept here.
- The server log shows `common_fit_params: failed to fit params to free device memory: n_gpu_layers already set by user
  to 99, abort` (a warning; the load continued).

## Verdict

The serve works. The fixed cost on this card is 5,874 MiB. The launcher over-estimates it by 382 MiB. With the display
on this card (idle free ~7,170 MiB) and margin 1,300 MiB, auto-sizing still gives nothing. The notebook's reading: "The
margin, not kernels, is the binding question here: 16,384 cells leaves ~500 MiB free."

## Corrections later

None to the measurement. The launcher's 8 GB fixed costs were later measured per mode and written into the 8 GB preset
(P034 entry, outside this range).

## What it changed

Every later run in this range pins BONSAI_KV_VRAM_CELLS (or BONSAI_VRAM_MARGIN) explicitly. The headless-detection
problem behind the margin is in events-p001-p029.md ("rig baseline" and "headless detection").

## Toolbox

- Method: load once with a pinned N, read used before and after, subtract the KV cells in VRAM and the staging window
  (host-tail cells x CellBytes/16). The rest is the fixed cost. It transfers to any model and any card.
- Model-specific: the cell size. Bonsai 27B has 16 attention layers x 4 KV heads x 256, K and V: 32,768 values per
  cell. q8_0 = 34,816 B per cell, q4_0 = 18,432 B. GDN layers have no KV cells.
- Card-specific: the desktop on the card (WDDM) takes 300-800 MiB here. On an 8 GB card that is 16k-45k q4_0 positions.
