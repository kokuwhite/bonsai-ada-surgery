## Question

How fast does this card decode and prefill at depth 0 to 120k with 16,384 q8_0 positions in VRAM and the rest on the
host?

## Why

P001 showed that only ~16k q8_0 positions fit with the desktop on the card. This run is the baseline record for every
later 8 GB change.

## Plan and gate

"Same serve as P1. bench/quick_tps.py (3 prompts, 400 tok, greedy, thinking off) at depth 0 / 4k / 16k / 32k / 64k /
120k. Record decode, prefill (first prompt), nvidia-smi used and free during each depth. Gates: every depth completes;
free VRAM never under 200 MiB; decode does not fall >30% between repeated prompts at the same depth (the demotion
signature). No pass/fail on speed: this is the record."

## Method

quick_tps.py sends "Say hi." first, then three prompts (code: LRU cache module; prose: transistor essay; bash: log
rotation script), 400 tokens each, temperature 0, thinking off, each prefixed with a filler of about `depth` tokens.
The first prompt at a depth evaluates the new part of the filler; the next two hit the prompt cache. Decode and prefill
come from the server's `timings` field. nvidia-smi used, free, memory clock and PCIe generation sampled every ~5 s.

## Deviations, incidents, void runs

None recorded.

## Verdict

Past the VRAM line decode is PCIe-bound. It falls ~2.4x at 32k and ~11x at 120k against in-VRAM speed. The notebook's
reading: "On this card positions in VRAM are the product; every MiB freed buys ~32 positions at q8_0 (~57 at q4_0)."

## Corrections later

- The "~32 positions per MiB at q8_0" does not match P001's own cell size: 1 MiB / 34,816 B = 30.1 cells. The q4_0
  figure (1 MiB / 18,432 B = 56.9) matches. The notebook does not correct this.
- P005 found that this serve ran without GGML_CUDA_BATCH_INVARIANT, so it took the Ada-tuned SOA_ISUM one-column
  kernel; P007/P008 measured +12.3% / +13.7% for the planar PT kernel. The record is valid for the bundle as it was.
- The 2026-10-11 TODO card (notebook line ~2315) uses this run as "our stock record P2 (N 16,384 q8_0): 37 tok/s at
  4k, 13.5 at 32k, 3.0 at 120k".

## What it changed

It set the goal of the mission: put more positions in VRAM. P005 (q4_0 vs drafting at equal VRAM) follows directly.

## Toolbox

- Method: a fixed probe (quick_tps: 3 prompts x 400 tokens, filler depth, first prompt measures prefill) run at the
  same depths on every configuration gives comparable rows across days. Transfers as is.
- Finding that transfers: when the KV cache spills to host RAM over PCIe gen 3, decode speed past the VRAM line
  depends on how many positions sit on the host, not on the kernels. On a small card, VRAM positions are worth more than
  kernel tuning.
- Model-specific: 16 attention layers carry KV; 48 GDN layers carry fixed recurrent state, so only the attention part
  grows with depth.
