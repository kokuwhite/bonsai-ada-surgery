## Question

Is the depth-0 text change between Oct 9 and Oct 10 (P91-P93) caused by prompt-cache reuse of the shared template
prefix?

## Why

P93's candidate explanation: "prompt-cache reuse of the shared template prefix (restore vs recompute -> different
batch split) depending on memory state at start."

## Plan and gate

No plan entry in the notebook. Script header: "P94: does prompt-cache state change greedy texts? One server per arm,
lookup_ab depth 0 twice in the same server (pass 2 meets a warm prompt cache). Arms: prompt cache on (default) / off
(LLAMA_ARG_CACHE_RAM=0)." No numeric gate.

## Method

Two servers (cacheon, then cacheoff). In each, lookup_ab.py at depth 0 twice (pass 1, pass 2), 11 items per pass.
Text shas compared with P85 (Oct 9, depth 0) and P92 pmask_d0 (Oct 10).

## Deviations, incidents, void runs

No plan entry in the notebook (script only).

## Verdict

Notebook: "in one server, lookup_ab d0 pass 1 vs pass 2: plain items change (pass 2 vs pass 1 3 diffs), with the
prompt cache on AND off. So not the prompt cache: state carried across requests in one server (most likely the
lookup ngram drafter's history: other drafts -> other verify batches -> other rounding on near-tie items). Texts are
stable for a fresh server with the same request history; compare only arms with the same history (as all A/Bs here
did)."

## Corrections later

None. (The Oct 9 vs Oct 10 split between fresh servers with the same history is not fully explained by this; the
notebook leaves it at "same history" as the rule.)

## What it changed

Test rule for all later text A/Bs: compare arms with the same request history in a fresh server, in one session
window.

## Toolbox (for the next model)

- Finding: with speculative drafting (MTP + n-gram lookup), greedy output on near-tie items depends on which drafts
  were proposed, because each verify batch size gives other floating-point rounding. The n-gram drafter learns from
  earlier requests in the same server, so request history changes text.
- Transfers to any engine with draft-and-verify decoding: identity tests need a fresh server per arm and the same
  request order.
