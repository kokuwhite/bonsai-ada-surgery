## Question

Is the packed KQ mask (1/16 of the f16 mask) exact with MTP drafting on today's engine, and how much VRAM does it
free?

## Why

Lead (notebook): "The mask is n_ctx x ubatch x 2 B: 128 MiB at 131k, 256 MiB at 262k (= 7,282 / 14,564 q4_0 VRAM cells
on this card). A packed (1-bit) mask is 1/16 of that. P22/P24: packed is exact without drafting, corrupts with MTP
drafting past 16k. A read-only code search for the drafting bug runs now (agent). If a fix is found: build on
prism-pstage, check texts packed vs f16 with drafting at 32k and 64k (byte-identical gate) before any speed arm."
Agent code read (no runs): "the packed path matches the f16 path line by line (fill, MMA loader, KV-max scan); the
packed mask is used only for batches >= 32 queries (prefill), so verify/decode keep f16. The P22b corruption has two
better explanations, both from that build and both fixed since: (1) staging buffers keyed by slot only, shared by the
target and the MTP draft context on different streams (today: keyed by cache, "kv<ptr>"); (2) the shared CUDA pool
race (patch 0045; preset pool off). P22b ran with the pool on and the old staging key."

## Plan and gate

Notebook: "Test (queue 49): 131k, N pinned 50,176, drafting preset + lookup, same bin, LLAMA_ARG_KQ_MASK_PACKED unset
vs 1; lookup_ab.py 11 items at 32k and 64k; test-backend-ops FLASH_ATTN_EXT. Gates: 22/22 texts identical; 0
one-token; tests pass; load free VRAM +100 to +128 MiB with packed. Pass -> speed arms with N raised by the saving
(131k and 262k), then upstream with the race explanation."

## Method

test-backend-ops FLASH_ATTN_EXT. Arm 0 (f16 mask) then arm 1 (packed), one server each: free VRAM at load, VRAM trace
every 10 s, lookup_ab.py at 32000 then 64000.

## Results

- FLASH_ATTN_EXT 2994/2994.
- Texts: d32000 11/11 same, d64000 11/11 same; 0 one-token.
- Mean tok/s (all 11 items): 32k f16 64.3 vs packed 64.9; 64k f16 50.2 vs packed 51.1.
- Load free: 341 (f16) vs 449 MiB (packed), +108. Trace min free: 115 vs 233 MiB, +118.
Per item (64k, f16 -> packed): quote 65.6 -> 66.8, 72.6 -> 74.5, 71.6 -> 73.2, 67.3 -> 68.4; plain 26.6 -> 26.8, 36.9 ->
37.2, 28.6 -> 28.9; edit 42.6 -> 43.3, 41.8 -> 42.4, 54.7 -> 55.5, 43.9 -> 44.7.
Notebook: "The P22b corruption was the old build's races (shared staging key / pool), not the packed mask - P22b/P24
conclusions corrected here."

## Deviations, incidents, void runs

- The script's per-arm grep for mask log lines used an inline sed that lost a backslash level (2026-10-09 lesson:
  "the P79/P82/P88 log-path greps were broken by this"); mem.txt has no mask-line counts. The VRAM numbers are from
  nvidia-smi and are valid.
- Small speed gain with packed at the same N (+0.9 % / +1.8 %): not a gate item.

## Verdict

All gates pass: 22/22 identical, 0 one-token, tests pass, load free +108 MiB (inside +100 to +128).

## Corrections later

None against P82. P82 corrects P22b / P24 ("packed corrupts with MTP drafting past 16k").
PR #13 review (4070, Ada): "packed vs f16 with drafting + lookup 11/11 at 32k and 11/11 at 64k; 240 MiB saved at
12 GB". main 05e349b (4070): packed mask on for 12 GB too: line 120,064 -> 128,000, decode 40.9 -> 48.2 at 131k.

## What it changed

Packed mask became part of the 262k 8 GB default (P84, PR #13: patches 0048/0049) and of the 12 GB recipe.

## Toolbox

- Lever: the KQ mask buffer is n_ctx x ubatch x 2 B in f16; a 1-bit packed mask is 1/16. On 8 GB at 131k it frees
  108 MiB = ~6.1k q4_0 cells; at 262k ~240 MiB.
- Lesson: a "corrupts with drafting" result from a build with known races must be re-tested after the races are
  fixed. Wrong conclusions stay in the notebook with the correction.
- Transfers to any llama.cpp model with flash attention and long windows (the mask cost scales with window x ubatch).
