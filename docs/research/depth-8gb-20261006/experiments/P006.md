## Question

Does q4_0 K/V cost the same quality on this card (Turing kernels) as on the 4070 (12 GB receipt)?

## Why

P005 picked B (q4_0, 38,656 positions) as the default candidate, conditional on this receipt. 12 GB receipt: q8_0 KL
0.00017 / top-1 flip 1 in 160; q4_0 KL 0.00218 / 1 in 48.

## Plan and gate

Gates written before the run (quoted):
- "the f16 base fits at 16,384 (if it does not, the run uses 8,192 and the entry says so; depths then differ);"
- "this card's q4_0 numbers are within 2x of the 12 GB receipt in both mean KL and flip rate (Turing kernels differ;
  a larger gap means q4_0 behaves differently here and needs its own investigation before any default);"
- "the README row for an 8 GB q4_0 default quotes this card's numbers, not the 4070's."

## Method

llama-perplexity writes f16-K/V logits as the base, then scores q8_0/q8_0 and q4_0/q4_0 against it: mean KL, max KL,
top-1 agreement ("Same top p"), ln PPL ratio. 4 chunks of 16,384 tokens.

## Results

Gates: f16 base fit at 16,384 PASS. q4_0 within 2x of the 12 GB receipt PASS (within 5% on mean KL and top-1). README row
quotes these numbers.

## Verdict

"q4_0 on this card matches the 12 GB receipt; B's cost is 1 flipped top token in 48." Decision: "B (q4_0, ~38.6k
positions in VRAM, no head) becomes the 8 GB default with the cost stated: q4_0 flips the top token on 1 in 48 positions
at 8k-16k depth vs 1 in 171 for q8_0; q8_0 stays a documented mode (BONSAI_CTK=q8_0) for exact-syntax work that fits in
16k."

## Corrections later

- P008 used the same recipe on bin-turing and found it does not exercise the one-column kernel (512-token ubatches);
  the q4_0 run there (receipts/p8-kl-newkernel-q4_0.log) gives the identical mean KL 0.002096 and top-1 97.900%.
- P032 (outside this range) measured task quality: HumanEval 157/164 with q4_0 vs 159/164 with q8_0 on the drafting
  mode; q4_0 stayed the default.

## What it changed

q4_0 K/V became the 8 GB default; BONSAI_CTK=q8_0 a documented mode. The P006 KL numbers became the scale for the
P008/P8c kernel gate (0.000167, 99.417%).

## Toolbox

- Method: KL and top-1 agreement vs an f16-K/V base at real depth (8k-16k) is a cheap, model-level quality receipt for
  any KV quantization. Repeat it on each GPU family: kernels differ.
- Lesson: llama-perplexity runs 512-token ubatches; it tests the prefill paths (MMQ, prefill attention), not the
  one-column decode path. Use `-b 1 -ub 1` to test decode kernels (P8c).
- Model-specific: Bonsai 27B has only 16 attention layers with KV, so q4_0 K/V costs ~1 top-1 flip in 48 at 8k-16k;
  a model with more attention layers can differ.
