## Question

Does the server stay healthy with lookup drafting at 64k depth for 10+ minutes, with no VRAM squeeze and no decode
fall?

## Why

12 GB review on PR #9 asked for a soak.

## Plan and gate (as frozen before the result)

"Drafting preset with lookup (PR #9 launcher copy), bin-lookup, lookup_ab.py --depth 64000 run 3 times back to back on
one server; free VRAM every 2 s. Gates: server alive, no nvlddmkm event, min free >= 60 MiB, decode of run 3 within 3 %
of run 1." Note added before it ran (4070 session): "run part of it with a normal desktop on the card (Cary's browser),
not only idle."

## Method

One server; three lookup_ab.py rounds at 64k (11 items each); nvidia-smi free VRAM every 2 s; at the end a System-log
query for nvlddmkm / WHEA events in the last hour.

## Deviations, incidents, void runs

- Runs 2 and 3 found the quote prompts in the prompt cache (wall 21.7-35.9 s instead of ~300 s); edit items still
  re-prefilled (~285-291 s). So rounds 2-3 do not run the same work as round 1, and decode rose instead of falling.
- The driver-event query covers the last 60 min only; the soak lasted 89 min (5,335 s).
- No record says whether part of the soak ran with Cary's browser on the card (the 4070 session's note).
