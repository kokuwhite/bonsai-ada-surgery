## Question

Is memory +1000 MHz stable for 60 min under server load with byte-identical greedy output, when the clock is set
before the server starts?

## Why

Both P39c attempts died seconds after a live Afterburner switch. "P42 (plan): set the clock with no server running,
then start the server. +1000 60 min, then stock 20 min reference."

## Plan and gate (as frozen before the result)

Plan text: "set the clock with no server running, then start the server. +1000 60 min, then stock 20 min reference."
Gates carried from P39b/P39c: every text identical to the stock text of the same (depth, prompt); no nvlddmkm event;
drift (last 2 min vs first 2 min) < 2 %.

## Method

Stop server -> apply slot 2 -> start server -> p9_soak 3,600 s (depths 4k/16k/32k, two alternating prompts, 300
tokens, greedy) -> stop -> apply slot 5 -> start server -> p9_soak 1,200 s -> stop -> compare texts against the
stock set.

  22:1x: right engine." (serve.txt: 22:05:33.)

## Verdict

"101 requests at +1000 in 60 min + 33 stock requests: texts not in the stock set 0 (1 variant per key). No nvlddmkm /
WHEA / bugcheck event." "Drift gate (< 2 %) fails for both arms equally (stock +1.7 / +3.8 / -3.3, +1000 -3.2 / -5.0 /
+0.7): request-mix noise, not heat (same both). Decision: +1000 is a documented opt-in (+2.5 % drafting decode, ~+8 %
plain decode) for this card with this receipt; never a launcher default. Never switch clocks while a server runs (P39
deaths). Cap +1000."

The per-prompt numbers support the request-mix reading: the first-vs-last windows mix the two prompts.

## Corrections later

None. docs/8GB.md (PR #12): "drafting preset: +2.4-2.7 % at 4k-32k, 60-minute soak with identical text; +1250 MHz
faulted after about 10 minutes, and +1500 MHz stopped the PC; set the clock before the server starts."

## What it changed

Memory +1000 documented as an opt-in for this card. Rules: clock set before the server starts; cap +1000; never a
launcher default.

## Toolbox (for the next model)

- Transfers: memory OC gains much less in a drafting (2-column verify) mode than in plain decode (+2.6 % vs +7.7 %
