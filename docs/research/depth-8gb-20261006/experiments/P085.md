## Question

Does the PR #13 launcher, auto-sized with nothing pinned, reproduce P84's H262 result on this card?

## Why

P84 pinned N 59,904. Users get the auto-sizing launcher: window 262144 when the engine has packed mask + STAGING_FRAC
and >= 24 GB RAM; packed mask on; shared pool on for 8 GB (BONSAI_POOL_MIB 48); Small FixedMiB += mask(Ctx, ubatch,
packed) - f16 mask at 131072 - pool; partial staging with BONSAI_STAGE_CELLS 81920 (8 GB only).

## Plan and gate

Notebook: "Expected N ~59,136 (P84 pinned 59,904), trace min ~130 MiB. Test copy start-server-262test.ps1 (+ BONSAI_BIN),
bin-pmask: sweep 4k-128k, fresh 60k x2, lookup_ab d0 + d64000. Gates: launcher lines show 262144 / packed / pool /
staging; N within 1,024 of 59,136; decode within 2 % of P84 H262; trace min >= 60 MiB everywhere; 0 one-token; lookup
texts at d0 = P79 rel_d0 (11/11)."

## Method

Sweep server (quick_tps 4k/32k/64k/96k/128k, trace), two fresh 60k servers (trace), one lookup server (d0 then d64000,
trace).

## Results

## Deviations, incidents, void runs

- The run waited 94 min (18:27-20:01) for the lookup filler; fixed the same evening: fillers yield to queued jobs.
- N 58,880 is 256 cells below the formula estimate (59,136); inside the 1,024 gate.

## Verdict

All gates pass: launcher lines, N within 1,024, decode within 1.7 % of H262, trace min 110-116 MiB, 0 one-token, d0
texts 11/11 = P79.

## Toolbox

- Method: after a pinned A/B, always run the real launcher end to end (auto-sizing can land a few hundred cells off).
- The launcher line set (window, VRAM line, staging range, pool, mask) is the receipt that the user's config equals
  the tested one.
- Transfers: auto-sizing from free VRAM at start makes N depend on the desktop's VRAM use (here 58,880 vs 59,392 in
  P86 with the same launcher).
