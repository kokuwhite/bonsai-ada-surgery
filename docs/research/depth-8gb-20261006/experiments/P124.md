## Question

With the launcher-sparse defaults, does product-sparse lose nothing at 4k-128k against the released engine, and does
it give >= 1.8x dense at 160k and 245k, inside VRAM?

## Why

Step 3, item 3 of the sparse bundle plan on #21 ("Your release-style sweep from the proposal"). The 4070 also asked
for the 245k trace minimum, sparse vs dense, to decide whether the page-bound reserve can be trimmed.

## Plan and gate

Script header: "Arms: def sweep 4k / 32k / 64k / 96k / 128k (one server); deep_def 160k -> 245k (launcher default)
vs deep_off 160k -> 245k (BONSAI_SPARSE=0); fresh 60k x2 (default). Gates (declared here, before the run): 4k-128k
decode >= the bundle-20261013 release check (P126) - 3 % [reference changed 2026-10-14 before the run, per the 4070
on #21; was bundle-20261011 P113: 53.9 / 47.9 / 38.0 / 27.9 / 16.9]; 160k and 245k: default >= 1.8x deep_off; 0
one-token; trace min free >= 60 MiB in every arm; post the launcher kv lines."

Floors from P126 (53.7 / 47.5 / 36.1 / 26.0 / 16.3) minus 3 %: 52.1 / 46.1 / 35.0 / 25.2 / 15.8.

## Method

Arms in order: def (sweep), deep_def, deep_off, fresh60k_r1, fresh60k_r2; one server each; 10 s trace; launcher kv
lines; sparse_mask line count.
