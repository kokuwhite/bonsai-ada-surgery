## Question

With int8 page bounds (half the reserve), how many line cells come back on 8 GB, and is 64k with the launcher
default now within 5 % of BONSAI_SPARSE=0?

## Why

P123: the routing fix holds, but the f16 reserve (245 MiB, 13.8k cells) costs -7.0 % at 64k, above the 4070's 5 %
default rule. The 4070's int8 bounds (514 B per host cell, ~124 MiB at 262k) should give ~7k cells back. On #21
(05:57Z) the 4070 called P127 "the deciding run"; patch 0055 (draft PR #56) and PR #49 stay draft until P124 / P127
pass on c8bbb1898.

## Plan and gate

Script header: "P127 (#21, the 4070's request after D22): P123 on product-sparse c8bbb1898 (int8 page bounds, 514 B
per host cell at page 64) with launcher-sparse 8a47ffe (...). Builds 75-real inside the job (...), op tests, then 64k
default vs BONSAI_SPARSE=0 alternated x2. Gates (declared here, before the run): op tests 0 FAIL; the launcher prints
'VRAM line A -> B' with B about 7k cells above P122's 48,640; 64k default within 5 % of BONSAI_SPARSE=0 (the 4070's
default rule; my 2 % gate reported too); 0 sparse ops at 64k; 0 one-token; trace min free >= 60 MiB."

## Method

(Planned.) Build with up to 3 tries (a build counts only if the exe exists and the log has no "build stopped" or
error lines); copy to bin-psparse8 (+ missing DLLs from bin-0046); op tests; then off_r1, def_r1, off_r2, def_r2 at
64000 with a 10 s trace, kv / "VRAM line" launcher lines and the sparse_mask count.
