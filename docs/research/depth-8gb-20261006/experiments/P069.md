## Question

With alternated server starts, does poolsync give 0 failures while the old engine fails?

## Why

P67 showed the race is intermittent (pool-on control passed once). P68's 0/9 needed a control in the same session.

## Plan and gate

Notebook: "P69 (plan, front of queue): alternated x6: bin-poolsync pool on / bin-tier pool on, fresh 60k quick_tps.
Gates: poolsync 0 one-token in 6 runs while bin-tier fails in >= 3 of 6 -> the fix works (P(0/6 | 70 % rate) <
0.1 %). If bin-tier also passes most runs, the test cannot separate them -> more runs."

## Method

12 server starts, alternated: poolsync r1, tier r1, poolsync r2, tier r2, ... r6. Each: fresh quick_tps --depth 60000
(3 requests: code 59,953 tokens, prose 512, bash 516).
