## Question

With the pool still on, which component turns the 1-token answers off: MTP, patch 0041, the draft window, or the
head file?

## Why

P64 partial: the bug is not f16 prefill and not lookup. Remaining suspects: "MTP draft context with a fresh long
prompt (draft window 16384), 0041 tier prefill, the tiered cache on this card. Steps that extend the prompt (P40c,
P56) never failed; no-head fresh 60k worked (P16b, old engine)."

## Plan and gate

Notebook: "P65 (front of queue): fresh 60k quick_tps, drafting preset unless noted, LLAMA_ARG_LOG_VERBOSITY=4 in every
arm: a) bin-tier BONSAI_SPEC=0 (no MTP) b) bin-lookup (pre-0041) c) bin-tier BONSAI_DRAFT_WINDOW=65536 d) bin-tier
long mode (no head file). Reading: which arm answers normally isolates the cause."

## Method

4 arms, one server each, quick_tps --depth 60000 (fresh). Launcher lines and server logs saved.

## Deviations, incidents, void runs

- The hotfix (P64) changed the shared launcher copy while this queued job ran. The arms after 16:50:22 ran without
  the pool. The nospec arm started before the change but has no MTP draft context.
- Receipt note: without MTP the launcher picks the long-mode preset (ub 1024, f16 prefill to 65536, more VRAM cells),
  so nospec / longmode prefill (305 tok/s) is not comparable to the drafting arms (~248-250).

## Verdict

Void as a component test. Consistent with "pool off passes".

## Corrections later

P67 amended: "+ pre0041 with pool (bin-lookup), + a pool-on control on bin-tier." P67 used a pinned pool-on copy
(start-server-maintest-pool.ps1). P67: pre-0041 engine with the pool 0/3, and the pool-on control also 0/3 (the race
is intermittent).

## What it changed

Nothing directly. It showed that queued jobs must use a pinned launcher copy per experiment.

## Toolbox

- Incident lesson: never edit a launcher file that a queued job uses; give each experiment its own pinned launcher
  copy (later practice: start-server-<test>.ps1 per job).
- A no-MTP arm also changes the preset (ubatch, f16 cap, VRAM line); a "one change per arm" plan must check what the
  launcher derives from the switch.
